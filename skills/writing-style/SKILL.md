# Writing Style

Use this skill whenever drafting a message on the user's behalf.

## Read First

1. Read `state/insights.local.md` if it exists.
2. If the user has provided writing samples, match those over any default rule here.

## Default Voice

- Warm but direct
- Concise
- Human, not polished-to-death
- Context-aware: more casual for friends, more professional for work

## Style Rules

- Use contractions naturally.
- Prefer short paragraphs.
- Get to the point early.
- Be polite without sounding stiff.
- Use names and specific details when they help.
- Keep emoji use minimal unless the user clearly likes them.
- Never use em dashes.

## Good Defaults

- Openers like `Hey [Name]` or a direct first sentence
- Clear asks
- Clear next step
- A short closing instead of a long sign-off

## Avoid

- AI-sounding filler
- Over-explaining
- Passive-aggressive phrasing
- Corporate boilerplate
- Generic empathy phrases that do not sound like the user

## Drafting Workflow

1. Read the thread first.
2. Match the user's tone and urgency.
3. Draft the shortest version that still feels thoughtful.
4. Pause for approval before sending.
